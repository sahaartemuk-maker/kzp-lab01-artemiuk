# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант
- Тема: Розгортання Java-проєкту та базова обробка даних
- Предметна область: Спортивні тренування
- Номер варіанта: 2
- Рівень: 3
- Операційна система: macOS (Apple Silicon)

## 2. Мета роботи
Створено Maven-проєкт консольної програми, яку відтворено збирають і запускають
на Windows, macOS та Ubuntu; налаштовано тести, SpotBugs, виконуваний JAR,
GitHub Actions та роботу через Issues і Pull Request.

## 3. Постановка задачі
Формат запису: `date:String; kind:String; minutes:int; distanceKm:double; calories:int`.

Показники: кількість коректних записів; сумарний час; сумарна дистанція;
найбільша витрата калорій.

## 4. Структура програми
Потік даних: `Main` (аргументи) → `FileReport.readLines` (UTF-8) →
`TrainingStats.compute` (для кожного рядка `TrainingParser.validate`, потім
включення в показники) → `ReportFormatter.format` (один текст) → консоль і
`FileReport.writeReport`.

## 5. Інфраструктура
- Maven + Maven Wrapper, Java 21, UTF-8.
- JUnit 5.12.2 (scope test).
- SpotBugs 4.9.7.0 у фазі verify.
- maven-shade-plugin: виконуваний `target/lab01-1.0.0.jar`.
- Фільтрування ресурсів: `version.properties` → `--version` виводить `1.0.0+<build>`.
- GitHub Actions: матриця ubuntu/windows/macos, `verify`, запуск JAR, артефакт `jar-<os>-<run>`.

## 11. Відповіді на контрольні питання
1. `pom.xml` описує проєкт для Maven: координати, версію Java, кодування, залежності, плагіни.
2. `test` компілює й запускає тести; `verify` додатково пакує JAR і запускає перевірки (SpotBugs); `package` — компіляція, тести та JAR.
3. Wrapper завантажує фіксовану версію Maven, тому збірка однакова на будь-якому комп'ютері без установленого Maven.
4. `main` — точка входу, з якої JVM починає виконання; отримує аргументи командного рядка.
5. Примітивний тип зберігає значення напряму і не може бути `null`; `String` — посилальний тип, об'єкт із методами.
6. Ділення `int / int` відкидає дробову частину; приведення до `double` зберігає її.
7. Буде кинуто `NumberFormatException`.
8. Інакше користувач не дізнається, що дані втрачено, і результат буде хибним без пояснення.
9. З лімітом `-1` порожнє останнє поле зберігається в масиві, тому кількість полів перевіряється правильно.
10. `Path.of` сам підставляє роздільник поточної ОС; рядок із `\\` не працює на macOS та Ubuntu.
11. Стандартне кодування ОС може бути не UTF-8, і українські символи зіпсуються.
12. `%n` вставляє роздільник рядка поточної ОС, `\n` — завжди LF.
13. Порожній рядок, кількість полів (5), непорожні дата й вид, цілі `minutes` і `calories`, число `distanceKm`, усі числа ≥ 0.
14. Тест з кількома записами й відомим результатом, порівняння з похибкою `assertEquals(expected, actual, 0.0001)`, а також випадок без коректних записів (ділення на нуль).
15. Знаходить типові помилки в байт-коді без запуску програми.
16. Автоматично збирає й тестує кожну зміну на трьох ОС і публікує JAR.
17. Версія описує стан коду (змінює розробник), номер збірки — конкретний запуск CI. За SemVer усе після `+` — метадані збірки, а крапка утворила б нову версію.
18. Кроки відтворення, очікуваний і фактичний результат.
19. Чи використовувався ШІ, які інструменти й ролі, власний внесок і підтвердження розуміння коду.
20. DevOps консультує щодо Maven, CI й пакування; Валідатор шукає крайові випадки й оформлює дефекти.
