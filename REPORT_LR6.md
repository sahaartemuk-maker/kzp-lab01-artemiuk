## 2. Мета роботи
Створено Python-пакет `kzp_lab06` (тека `python/`), який читає CSV тренувань через `csv.DictReader`,
перетворює поля на типізовані значення, виконує відбір, агрегування й пошук унікальних значень, записує
детермінований текстовий звіт і працює як CLI. Поведінку перевіряє `pytest`, стиль — `ruff`, пакет
збирається у wheel і встановлюється в окреме середовище.

## 3. Формат CSV
Файл `python/data/input.csv`, UTF-8, роздільник — кома, перший рядок — заголовок:

| Поле | Тип після перетворення | Правило |
|---|---|---|
| `date` | `str` (ISO `YYYY-MM-DD`) | перевіряється `date.fromisoformat` |
| `kind` | `str` | обрізаються пробіли, внутрішні пробіли нормалізуються; не порожнє |
| `duration` | `int`, хв | ціле ≥ 0 |
| `distance` | `float`, км | скінченне (не NaN/inf) ≥ 0 |
| `pulse` | `int`, уд/хв | ціле ≥ 0 |

Приклад екранованого рядка (вид з комою): `2026-09-07,"Біг, інтервали",40,6.0,168`.

Контрольний набір (8 записів): дубльовані види (`Біг` ×2, `Велосипед` ×2), граничне значення
`duration=45` (входить у відбір), нульова дистанція (`Йога`, 0.0), текстове поле з комою, однакова
найбільша тривалість 90 хв у двох записах (обирається перший).

Правило порожнього входу: файл без жодного рядка (немає заголовка) → `DataError` «CSV порожній», код 1;
файл лише із заголовком → коректний звіт із 0 записів і «—» замість показників.
Вхідний файл не змінюється (перевіряється тестом побайтово). У порівнянні з Java-частиною (ЛР4–5),
де пульс замінено калоріями, тут використано поля точно за таблицею варіантів методички.

## 5. Перетворення даних
- **Список** — результат `parse_records` (порядок рядків файла) і відібрані записи
  `[r for r in records if r["duration"] >= min_duration]`.
- **Множина** — `{str(r["kind"]) for r in records}` (дублікати зникають).
- **Словник** — `{kind: sum(...) for kind in sorted(unique_kinds(records))}` — сумарна дистанція за видом.
- **Comprehensions** — list-comprehension відбору й розбору рядків, set-comprehension видів,
  dict-comprehension агрегатів, генераторні вирази в `sum`.
- `longest_training` написано звичайним циклом: правило «серед рівних — перший» у циклі прозоріше.

## 6. Функції
```python
def summarize(records, *metrics: str, min_duration: int = MIN_DURATION, **labels: str) -> dict[str, object]
```
`metrics` — кортеж назв числових полів, `labels` — словник підписів ключів результату, `min_duration=45` —
незмінне типове значення. Невідома метрика → `ValueError`; якщо після відбору записів немає, метрики дорівнюють `0.0`.

```python
summarize(records, "distance", "duration", distance="Дистанція")
# {'count': 6, 'Дистанція': 80.6, 'duration': 395.0}
```

## 7. Алгоритм аналізу
1. Відбір: `duration >= 45` (константа `MIN_DURATION`).
2. Агрегування: сумарна `distance` за `kind` серед відібраних.
3. Унікальні значення: множина видів за всіма записами.
4. Показники: середній пульс за всіма записами (1 знак), найдовше тренування (перше серед рівних).
5. Детермінований порядок: види й ключі словника сортуються; числа — `:.2f` (км) і `:.1f` (пульс);
   список видів розділяється `; `, бо назва виду може містити кому.

## 8. Обробка помилок
Кожна помилка даних — `DataError` з номером рядка файла (заголовок — рядок 1) і назвою поля:
«Рядок 2: поле duration має бути цілим числом», «Рядок 3: поле pulse не може бути від'ємним»,
«Рядок 1: відсутні стовпці pulse», «Рядок 2: поле kind порожнє», «Рядок 2: забагато полів»,
«поле distance має бути скінченним числом» (NaN/inf), «поле date має формат YYYY-MM-DD».
Першопричина зберігається `raise DataError(...) from error` (`ValueError`, `UnicodeDecodeError`, `csv.Error`).
Голий `except` не використовується; ловляться лише очікувані винятки.

Коди завершення CLI: `0` — успіх; `1` — помилка даних або однакові вхід/вихід (повідомлення в `stderr`,
файл звіту не створюється); `2` — помилка файлу (`OSError`, напр. відсутній вхід). `stdout`/`stderr`
явно переводяться в UTF-8.

## 15. Відповіді на контрольні питання
1. `pyproject.toml` — єдиний опис проєкту: назва й версія пакета, мінімальна версія Python, бекенд збірки,
   dev-залежності, консольна команда, налаштування pytest і ruff.
2. Віртуальне середовище ізолює залежності проєкту від системного Python та інших проєктів; його можна
   відтворити з `pyproject.toml`, тому до репозиторію воно не додається.
3. `newline=""` вимикає перетворення кінців рядків у Python і передає їх модулю `csv`, який сам правильно
   обробляє `\r\n` і перенесення рядка всередині лапок.
4. `DictReader` повертає словники `str → str` (рядки), а для зайвих полів — ключ `None` зі списком; типи треба перетворювати самостійно.
5. `split(",")` не враховує лапки: поле `"Біг, інтервали"` розпалося б на два, а лапки лишилися б у тексті.
6. Список — впорядкований, допускає повтори, доступ за індексом; словник — пари ключ→значення з унікальними
   ключами; множина — унікальні значення без гарантованого порядку, швидка перевірка належності.
7. Comprehension зрозуміліший для одного простого відбору або перетворення; цикл кращий, коли є кілька
   умов, побічні ефекти чи складне накопичення (як вибір першого серед рівних).
8. `*args` — кортеж додаткових позиційних аргументів, `**kwargs` — словник додаткових іменованих аргументів.
9. Типове значення обчислюється один раз при визначенні функції, тому змінний об'єкт (список, словник)
   спільний для всіх викликів і накопичує стан між ними.
10. `raise New(...) from error` записує початковий виняток у `__cause__`; traceback показує обидва, тож видно
    і зрозуміле повідомлення, і першопричину.
11. Розділення дає одну відповідальність на модуль: обчислення тестуються без файлів, формат звіту — без CSV,
    а зміна однієї частини не ламає інші.
12. `with` гарантує закриття файла після блоку, навіть якщо всередині виник виняток.
13. Детермінований порядок робить звіт відтворюваним: однакові дані дають однаковий текст незалежно від
    порядку рядків, і його можна порівнювати з еталоном у тестах.
14. Порожній файл без заголовка, файл лише із заголовком, а також відбір, що не залишив жодного запису.
15. Тест поведінки перевіряє зовнішній результат (повернене значення, файл, код завершення), а не внутрішні
    змінні; він не ламається при рефакторингу реалізації.
16. Файли `test_*.py` або `*_test.py`, у них функції `test_*` (та методи класів `Test*`).
17. `ruff check` — стиль і типові помилки (невикористані імпорти, небезпечні конструкції, застарілий синтаксис);
    `ruff format --check` — відповідність форматуванню без зміни файлів.
18. `0` — успіх; ненульовий для очікуваної помилки: у проєкті `1` — дані, `2` — файл.
19. Тести перевіряють поведінку, аналізатор — якість коду, пакетування — що пакет справді збирається й
    встановлюється; разом на трьох ОС вони виявляють різні класи проблем.
20. Вхідний CSV і його заголовок, правило порожнього входу, поріг відбору (45 хв), повний очікуваний звіт,
    коди завершення, команди запуску та результати pytest/ruff/CI.
