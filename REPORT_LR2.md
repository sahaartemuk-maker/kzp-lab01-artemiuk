# Звіт до лабораторної роботи № 2

## 1. Тема, номер і варіант
- Тема: Класи, record і інкапсуляція в Java-проєкті
- Предметна область: Спортивні тренування
- Номер варіанта: 2
- Операційна система: macOS (Apple Silicon), Java 21

## 2. Мета
Перебудувати предметну частину ЛР № 1: замість рядків і `String[] fields`
використати клас-сутність `Training`, перевірку інваріантів у конструкторі,
фабрику `fromCsv`, record `TrainingSummary` для підсумків і тести, які
підтверджують збереження зовнішньої поведінки.

## 3. Що змінено
Потік даних:

```
CSV-рядок → Training.fromCsv → new Training(...) → List<Training> → TrainingSummary.of → ReportFormatter
```

| Стан | ЛР № 1 | ЛР № 2 |
|------|--------|--------|
| Один запис | рядок і `fields[2]`, `fields[3]`… | об'єкт `Training` |
| Перевірка | `TrainingParser.validate` у циклі | конструктор `Training` + `fromCsv` |
| Набір даних | накопичувальні змінні в `TrainingStats` | `List<Training>` |
| Підсумок | окремі поля `validCount`, `totalMinutes`… | record `TrainingSummary` |
| Звіт | `ReportFormatter` | без змін змісту |

### Training (клас-сутність)
- Поля `private final`: `date`, `kind`, `minutes`, `distanceKm`, `calories`; лише геттери, без сеттерів.
- Інваріанти (з правил ЛР № 1): дата й вид — непорожній текст
  (`Objects.requireNonNull` + `isBlank`); хвилини, дистанція, калорії ≥ 0
  (нуль дозволено, як у ЛР № 1: наприклад, 0 км для йоги); дистанція — `Double.isFinite`.
- `fromCsv(line)` відповідає за структуру (порожній рядок, 5 полів, текстові поля,
  числові формати), конструктор — за інваріанти. Обійти перевірку неможливо.
- `toString()` → `2026-09-01 Біг: 45 хв, 8.50 км, 520 ккал` (`Locale.ROOT`);
  `label()` → `Біг (2026-09-01)` для звіту; `equals`/`hashCode` за значеннями.

### TrainingSummary (record)
`TrainingSummary(int count, long totalMinutes, double totalDistanceKm, int maxCalories, String maxCaloriesLabel)`;
компактний конструктор відхиляє від'ємні/нескінченні значення та `null`-мітку;
`of(List<Training>)` обчислює показники (перший серед рівних максимумів, як у ЛР № 1).

### TrainingStats
`compute(lines)` перетворює рядки на `Training`, помилку одного рядка перехоплює
(`catch IllegalArgumentException`) і додає як `Рядок N: причина`. Запис потрапляє до
списку лише після повної перевірки. Зовнішні методи доступу збережено.

### TrainingParser
Залишено тонким фасадом над `Training.fromCsv` для сумісності з ЛР № 1
(`TrainingParserTest` проходить без змін).

## 4. Доказ збереження поведінки
1. До перебудови (тег `v1.0.0`) збережено звіти для `data/input.csv` і
   додаткового файла граничних випадків (`NaN`, `±Infinity`, нулі, пробіли, 6 полів).
2. Після перебудови вивід порівняно `diff` — **відмінностей немає**.
3. Порівняння закріплено тестом `RegressionTest` (ресурси `src/test/resources/lr1-*`),
   рядки порівнюються без роздільників, тож тест однаковий на трьох ОС.

## 5. Тести
- `TrainingTest` — конструктор зберігає поля; нулі дозволені; `null`/порожні дата й вид;
  від'ємні хвилини/дистанція/калорії; `NaN`/`Infinity`; `fromCsv` коректний рядок, обрізання
  пробілів, неправильна кількість полів, хибне число, порожній/`null` рядок, порядок причин;
  `equals`/`hashCode`; `toString`.
- `TrainingSummaryTest` — рівність record, валідація компонентів, порожній список, обчислення.
- `RegressionTest` — звіт збігається з ЛР № 1.
- Тести ЛР № 1 (`TrainingParserTest`, `TrainingStatsTest`, `MainTest`, `BuildInfoTest`) — без змін.

## 7. Відповіді на контрольні питання (стисло)
1. Клас-сутність дає полям імена й типи, збирає перевірку в одному місці замість індексів масиву.
2. `private` — доступ лише в класі; `final` — поле присвоюється один раз.
3. Інкапсуляція приховує стан і не дає зовнішньому коду створити некоректний об'єкт.
4. У конструкторі — бо це єдиний шлях створення; некоректний об'єкт не існуватиме.
5. `requireNonNull` відсікає відсутнє значення, `isBlank` — порожній текст.
6. Без сеттерів стан не змінюється неперевіреними значеннями після створення.
7. Канонічний конструктор, методи-доступи, `equals`, `hashCode`, `toString`; поля `private final`.
8. Record — прозорий носій даних, не може успадковувати клас і мати додаткові поля екземпляра.
9. Record копіює посилання, а не вміст списку; список можна змінити ззовні.
10. `fromCsv` пояснює джерело даних і приховує розбір полів.
11. У циклі читання, щоб знати номер рядка й продовжити обробку.
12. Інакше хибний запис зіпсує статистику.
13. `toString` — для людей і налагодження; формат CSV — контракт обміну даними.
14. Щоб десятковий роздільник був крапкою на всіх ОС.
15. Arrange – Act – Assert: підготовка, виконання, перевірка.
16. `null`, порожній текст, від'ємні числа, `NaN`, нескінченність.
17. Порівняти звіт до й після на тих самих даних (`diff` + `RegressionTest`).
18. Вони фіксують контракт ЛР № 1; їх проходження доводить, що поведінка не змінилась.
19. `mvnw`, `.mvn/`, `pom.xml`, `.github/workflows/ci.yml`, шаблони Issues/PR.
20. `private final double distanceKm;` разом із `Double.isFinite` у конструкторі:
    дистанцію неможливо ні змінити, ні створити з `NaN`.
