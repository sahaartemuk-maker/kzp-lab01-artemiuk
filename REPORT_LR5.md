# Звіт до лабораторної роботи № 5 «Параметризоване сховище, винятки й CSV-експорт у Java-проєкті»

Студент: Артем'юк. Варіант 2 — «Спортивні тренування». Версія 5.0.0, тег `v5.0.0`.

## 1. Мета
Замінити пряме зберігання даних у списку на `Repository<T>`, додати власний виняток із ланцюгом причин,
описати CSV-стовпці анотацією `@CsvColumn` і реалізувати універсальний рефлексивний експортер; записувати
й читати файл через `Path`/`Files` з явним UTF-8 і довести round-trip.

## 2. Вихідний стан
Стан ЛР № 4 (`v4.0.0`): абстрактний `Training` з підтипами `IndoorTraining`/`OutdoorTraining`, `TrainingKind`,
потокові запити `TrainingQueries`, 72 тести, CI на 3 ОС. Номер варіанта, формат входу й звіту не змінено.

## 3. Клас варіанта, типи полів і ключ
Методичка називає клас `TrainingRecord`; у проєкті його роль виконує наявний абстрактний `Training`
(анотації стоять у ньому, експортер знаходить їх, проходячи ланцюжок підтип → `Training` → `Object`).

| Поле (Java) | Тип | `@CsvColumn` | Примітка |
|---|---|---|---|
| `calories` | `int` | калорії | замість «пульс» (погоджено в ЛР4, формат CSV не змінюється) |
| `date` | `String` | дата | лишається `String`, як у ЛР1–ЛР4 (еталонні звіти) |
| `distanceKm` | `double` | дистанція | скінченне, ≥ 0 |
| `kind` | `String` | вид | текст із CSV; категорія `TrainingKind` виводиться з нього |
| `minutes` | `int` | тривалість | ≥ 0 |
| `type` | `TrainingKind` | — | не експортується: однозначно відновлюється з `kind` |

Ключ round-trip: **дата + вид**. Підтип (`IndoorTraining`/`OutdoorTraining`) після імпорту обирає `Training.of`.

## 4. Параметризоване сховище `Repository<T>`
`add(T)` (відхиляє `null`), `addAll(List<? extends T>)`, `all()` → `List.copyOf` (незмінний, відокремлений знімок),
`find(Predicate<? super T>)` — приймає умову для `T` або супертипу (тест передає `Predicate<Object>`).
Сирі типи не використовуються; `Main` працює з `Repository<Training>`.

## 5. Анотація і рефлексія
`@CsvColumn` має `@Retention(RUNTIME)` (інакше `isAnnotationPresent` під час виконання не бачить її) і
`@Target(FIELD)`. `CsvExporter.annotatedFields(Class<?>)`:
1. обходить клас і суперкласи до `Object`, бере `getDeclaredFields()` (зокрема приватні);
2. лишає поля з `@CsvColumn`, сортує за `Field::getName` (порядок JVM не гарантований);
3. викликає `trySetAccessible()`; відмова → `DataStorageException`; жодного поля → `DataStorageException`.

Експортер не містить назв класів чи підтипів варіанта; тест `exporterWorksWithAnyAnnotatedClass` експортує
сторонній клас `Note`.

## 6. Формат CSV
- перший рядок — заголовки з `@CsvColumn`, далі значення в тому самому порядку;
- кодування UTF-8 (запис `Files.writeString`, читання `Files.readString`), роздільник рядків `\n` на всіх ОС;
- поле з комою, лапкою, `\r` або `\n` береться в лапки, лапка всередині подвоюється;
- файл перезаписується з `CREATE, TRUNCATE_EXISTING, WRITE`, батьківські теки створюються.

Фактичний заголовок:
```text
калорії,дата,дистанція,вид,тривалість
```
Екрановані рядки (з тестів `CsvExportTest`):
```text
700,2026-09-02,30.0,"Велосипед, інтервали",90
120,2026-09-03,0.0,"Йога ""ранкова""",40
0,2026-09-04,5.25,"Ходьба
з підйомом",60
```
`split(",")` розбив би перший рядок на 6 полів, тому читання виконує `CsvParser.parseDocument` — машина станів
над усім текстом, яка повертає записи, а не фізичні рядки.

## 8. Round-trip
`Repository.all()` → `CsvExporter.write` → `Trainings.readCsv` → `assertEquals(original, restored)`.
`equals` порівнює клас і всі поля, тому тест перевіряє порядок, числа, текст із комою/лапками/перенесенням
і підтип (`Плавання` → `IndoorTraining`, `Біг` → `OutdoorTraining`).

## 9. Помилки
| Рівень | Приклад | Реакція |
|---|---|---|
| Модель | порожній вид, від'ємні хвилини, NaN | `IllegalArgumentException` у конструкторі → у `fromCsvFields` загорнуто в `DataStorageException` з `cause` |
| Формат | 3 поля замість 5; незакриті лапки; символ після лапок | `DataStorageException` («Очікується 5 CSV-полів, отримано 3») |
| Значення | `abc` у стовпці «калорії» | `DataStorageException`, `cause` — `NumberFormatException` |
| Файл | файл відсутній; батьківський шлях — файл | `DataStorageException`, `cause` — `IOException` |
| Рефлексія | клас без `@CsvColumn`; доступ заборонено | `DataStorageException` |
| Порожні дані | порожній набір → файл лише із заголовком → порожній список; файл 0 байт → помилка | описано контрактом |

Невідомий вид не є помилкою: за ЛР3 `TrainingKind.fromLabel` дає `OTHER`, а текст `kind` зберігається дослівно;
тому замість «хибного enum» тестується порушення інваріанта (порожній вид). Виняток ніде не поглинається:
`Main` друкує повідомлення й причину та повертає код 1; `Trainings.readCsv` додає номер запису й зберігає `cause`.

## 10. Тести
- `RepositoryTest` (6): порядок, незмінність і відокремленість знімка, `Predicate<Object>`, `null`, мета-анотації, `getCause()`.
- `CsvExportTest` (16): заголовок, екранування, рядок із комою, довільний клас, клас без анотацій, round-trip, `TRUNCATE_EXISTING`,
  порожній набір, порожній файл, парсер (коми/перенесення/`""`/`\r\n`), незакриті лапки, кількість полів, число, інваріант,
  відсутній файл, помилка запису.
- `MainTest` (+2): `--export` і код 1 з причиною.

Разом 96 тестів, 0 падінь; `RegressionTest` підтверджує, що основний звіт ЛР1 не змінився.
